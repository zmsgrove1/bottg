# Instagram Post Monitor → Telegram

Раз в сутки проверяет список Instagram-аккаунтов и присылает в Telegram ссылки
на посты, вышедшие с прошлой проверки.

## Как это работает

- Список аккаунтов и "последний увиденный пост" по каждому хранится в Supabase (таблица `ig_accounts`)
- Скрипт `check_posts.py` идёт по списку, через `instaloader` смотрит последние посты
  каждого аккаунта, сравнивает с сохранённым `last_post_id`
- Новые посты — одним сообщением (или несколькими, если много) в Telegram
- Обновляет `last_post_id`/`last_post_date` в Supabase, чтобы при следующем запуске
  не присылать те же посты повторно
- Ошибка по одному аккаунту (например, Instagram временно ограничил доступ) не
  останавливает проверку остальных — в конце придёт отдельное сообщение со списком
  тех, кого не удалось проверить

## Шаг 1 — Supabase

1. Создать проект на supabase.com (бесплатного тарифа достаточно)
2. В SQL Editor выполнить содержимое `schema.sql`
3. Добавить свои 35-40 аккаунтов:
   ```sql
   insert into ig_accounts (username) values
     ('username_1'),
     ('username_2');
   ```
   (username — как в ссылке instagram.com/USERNAME, без @)
4. В Project Settings → API взять `Project URL` (это `SUPABASE_URL`) и
   `service_role` key (это `SUPABASE_KEY` — НЕ anon key, нужен именно service_role,
   так как скрипт пишет в таблицу)

## Шаг 2 — Telegram-бот

1. В Telegram написать `@BotFather` → `/newbot` → следовать инструкциям →
   получить токен (`TELEGRAM_BOT_TOKEN`)
2. Написать что-нибудь своему новому боту (любое сообщение, чтобы он вас "увидел")
3. Узнать свой `chat_id`: открыть в браузере
   `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates` и найти `"chat":{"id": ...}`
   в ответе — это и есть `TELEGRAM_CHAT_ID`

## Шаг 3 — Render

1. Залить эту папку в свой GitHub-репозиторий
2. В Render: New → Cron Job → подключить репозиторий
3. Build Command: `pip install -r requirements.txt`
4. Start Command: `python check_posts.py`
5. Schedule: `0 6 * * *` (раз в сутки в 06:00 UTC = 11:00 по времени Астаны;
   поменяйте под удобное вам время)
6. В Environment добавить переменные:
   - `SUPABASE_URL`
   - `SUPABASE_KEY`
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`
   - `PAUSE_BETWEEN_ACCOUNTS` = `15` (пауза в секундах между проверкой аккаунтов —
     чем больше, тем безопаснее для аккаунта/IP, но дольше общее время выполнения)

Если используете `render.yaml` (Blueprint) — Render сам подхватит настройки,
останется только вписать значения секретных переменных в панели.

## Важно про надёжность Instagram-доступа

Скрипт работает без логина в Instagram (анонимно) — это самый безопасный вариант
с точки зрения риска блокировки чьего-либо личного аккаунта, но Instagram
периодически (и непредсказуемо) начинает жёстче ограничивать анонимные запросы.
При 35-40 аккаунтах раз в сутки с паузами это обычно работает, но 100% гарантии
стабильности нет — это ограничение самого Instagram, а не скрипта.

Если через какое-то время начнёте получать много ошибок в отчётах:

**Вариант А — логин через сессию.** Завести отдельный (не основной) Instagram-аккаунт,
один раз локально выполнить `instaloader --login=ВАШ_ЮЗЕРНЕЙМ`, это создаст файл
сессии — его можно загрузить в Render как Secret File и указать переменные
`IG_SESSION_USERNAME` и `IG_SESSION_FILE` (поддержка уже есть в скрипте).
Риск: этот аккаунт теоретически может получить временное ограничение от Instagram
за частые автоматизированные запросы — поэтому используйте отдельный, не личный
и не бизнес-аккаунт.

**Вариант Б — платный API** (например, Apify Instagram Scraper actor или сервис
на RapidAPI). Стабильнее, но появляется небольшая стоимость за запросы. Если
дойдёт до этого — скажите, перепишу скрипт под конкретный API.

## Проверка вручную (локально, до деплоя)

```bash
pip install -r requirements.txt
export SUPABASE_URL=...
export SUPABASE_KEY=...
export TELEGRAM_BOT_TOKEN=...
export TELEGRAM_CHAT_ID=...
python check_posts.py
```

## Первый запуск

При первом запуске для каждого аккаунта скрипт просто "запоминает" текущий
последний пост как точку отсчёта — историю за прошлое присылать не будет
(иначе первый отчёт вывалил бы кучу старых ссылок). Уведомления о новых постах
начнутся со следующей проверки.
